# Dev log: w1 (CLI)

`docs/how-it-works.md`. Interfaces: see dev-log/main.md.

## Log

- 2026-10-20 Cancellation. New `src/cancel.rs`: SIGINT/SIGTERM set a flag (signal-hook 0.4,
  `flag::register_usize`; libc for `killpg`). Every child (test commands and git) is spawned as a
  process-group leader and waited on with a 10 ms poll; when the flag is set, the group gets
  SIGTERM, then SIGKILL after 1 s if anything is left, and the wait fails. The error unwinds
  through `Workspace::drop`, which removes the worktrees (also with `--keep-worktrees`), and
  `cli::main` exits 128+signal with `sundgren: cancelled`. Handlers are installed only for
  `run`. Cleanup git runs in its own group so a terminal Ctrl-C doesn't interrupt it. A worktree
  path is registered before `git worktree add`, so a cancelled add is removed too (only if the
  path didn't exist before). `cancel::check()` between phases covers the CPU-only parts (diff).
- Tests: `src/cancel/tests.rs` (group stopped, SIGKILL after grace, output capture);
  `tests/e2e/test_cancel.py` runs the real binary with a test command that records its pid and a
  background child's pid, then sends the signal: base run (SIGTERM 143, SIGINT 130), patched
  run, a command that ignores SIGTERM (killed after the grace), worktree setup (a post-checkout
  hook that sleeps), and `--keep-worktrees`. Each asserts the exit code, exit within 2 s, the
  pids gone, and no worktrees or `sundgren-*` temp dirs. Typical exit: ~0.1 s; 1.1 s when
  SIGTERM is ignored. The pre-cancellation binary fails all six and leaks the sleeps.
- Note for main: children are no longer in sundgren's process group, so killing sundgren's group
  from outside (or SIGKILL) won't reach them. Send SIGTERM to sundgren and let it stop them.
- 2026-10-20 (main's request) Linux: each child gets PR_SET_PDEATHSIG(SIGKILL) in pre_exec, with
  the getppid() check, so a direct child dies if sundgren is SIGKILLed or crashes. Known limit:
  grandchildren (cargo's test binaries, a shell's background jobs) escape that; only the
  SIGTERM path stops the whole group. Not on macOS. e2e: `test_sigkill_takes_the_direct_child_along`
  (fails without the prctl).
- Deleting a large `out/` (cargo target dir) on cancel can take longer than 2 s; not avoidable.
- 2026-10-20 `run --check`, preset `checks`, `--all-tests`. `src/cli/check.rs`: collects every
  problem (codes and exit precedence as agreed with main), checks the patch in a patched-only
  worktree (`Workspace::patched_only`, private temp dir, removed), computes selection and
  commands from the applied diff like `run`, runs the preset checks in the repo root with the
  preset env and `{out}` in a temp dir. stderr gets one line, the first problem with the deciding
  exit code. `schema/check.schema.json`. Check messages: a missing program says so; Python's
  "No module named 'x'" becomes "x isn't installed for <python>: ..."; otherwise the command, its
  exit and its last output line. `--all-tests` (conflicts with `--tests`) -> run_all, reason
  "--all-tests given". Tests: `tests/e2e/test_check.py` (9, all via run_sundgren so leftovers
  are asserted), two more cancel tests (`--check` during the worktree and during a check),
  unit tests in `src/cli/check/tests.rs`, `src/run/tests.rs`, presets tests.
