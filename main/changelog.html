Changelog#

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

Unreleased#

0.2.2 - 2026-10-20#

Added#

  • An examples page on the docs site with common cases in Python and Rust: a patch that only touches tests, one that changes source code, one that changes a fixture or test helper, running only some tests with --tests (down to one case of a parametrized pytest test), and your own commands with placeholders. (#8)

  • The docs site’s header shows the release it documents, with links to it on GitHub and PyPI. (#9)

  • Docs for main, with changes that aren’t released yet, at https://axean.github.io/sundgren/main/. A banner marks them as a preview and links the commit they were built from. (#11)

Changed#

  • The docs site’s home page is now a short overview, with links to the other pages. (#8)

0.2.1 - 2026-10-19#

Added#

  • Two pages on the docs site: “How it works”, and a reference of every option, preset key, placeholder, exit code and warning. (#5)

Changed#

  • sundgren is now a self-contained program. uv tool install sundgren (or pipx) installs a compiled binary for Linux and macOS (x86_64 and arm64), and running it no longer needs Python. Building from source needs Rust 1.88 or newer. (#5)

  • Error and warning messages are worded differently. (#5)

  • The JSON report writes non-ASCII text as UTF-8 instead of \u escapes. (#5)

  • Command-line arguments, paths and lcov files must be valid UTF-8, and lcov numbers must be plain ASCII digits. (#5)

0.1.2 - 2026-10-18#

Added#

  • Logo: the README shows it instead of the title. The docs site shows it at the top of the page, with the round icon in the header and as the favicon. Light and dark variants. (#2)

  • Changelog page on the docs site, linked from the header. (#2)

  • Line coverage of sundgren’s own code in CI: measured in-process over everything outside tests/ and docs/examples/, with a summary table, an HTML report artifact and a README badge. (#3)

Changed#

  • The docs site uses the logo’s colours: an orange accent (darker in light mode for contrast) and warm greys, in light and dark mode. Note callouts use the accent instead of blue. (#2)

0.1.1 - 2026-10-18#

Added#

  • Docs site at https://axean.github.io/sundgren/ with a Python and a Rust example: skipping test_divide, or marking it #[ignore], makes divide go dark. Each shows its project, patch and command, a graphic drawn from the recorded JSON report, and the text and JSON reports. (#1)

  • Docs examples in docs/examples/: a project, a patch, the exact commands and their recorded output. The docs tests rerun them in CI (the Python example on 3.11–3.14, the Rust one with the cargo-tarpaulin preset on rustc 1.99.1 and cargo-tarpaulin 0.37.5) and fail on any difference; tools/docs_examples.py --update re-records. (#1)

  • A docs test that fails if a docs page has a code block that isn’t an include of a tested example file. (#1)

  • Docs workflow: the docs tests and a strict Sphinx build run on every push and PR. (#1)

  • This changelog, and a versioning policy in the README: before 1.0, a breaking change to the CLI, the report schema, the preset format or the built-in preset names bumps the minor version. (#1)

  • README badges for CI, PyPI, Python versions, license, docs, Ruff, Black style and mypy. (#1)

Changed#

  • The version is set in pyproject.toml (uv version --bump patch); sundgren.__version__ reads the installed package metadata. (#1)

  • Stricter release checks (tools/release.py): the tag must be vX.Y.Z and equal the pyproject.toml version, and the changelog must have a section for it and an empty ## Unreleased. The GitHub release notes are that section. (#1)

  • The PyPI publish waits for the docs tests and a strict docs build; the site deploys to GitHub Pages after the publish. (#1)

0.1.0 - 2026-10-18#

Note

First release. This entry was written after the release.

Added#

  • sundgren run: runs a coverage command on the base tree and on the patched tree (git worktrees), diffs the two lcov files with line numbers mapped through the patch, and reports what the patch did to lines, branches, functions and test outcomes.

  • sundgren diff for two existing lcov files, sundgren ingest (a normalized lcov snapshot as JSON) and sundgren presets.

  • Built-in presets pytest (coverage.py + pytest, selecting the test files the patch touches), cargo-llvm-cov and cargo-tarpaulin. Custom presets go in sundgren.toml or [tool.sundgren.presets]; any tool that writes lcov works through --cmd and --lcov.

  • JSON report with schema sundgren.delta/1: line categories (lost, gained, new_hit, …), branch categories, function status (went_dark, lit_up, …), JUnit test outcomes, a per-directory tree rollup and warnings. --format text prints a summary.

  • --repeat N reports lines whose status varies across runs as flaky. --full keeps unchanged entries, --counts adds hit-count changes.

  • Exit codes: 0 ok, 1 tool or run failure, 2 usage error, 3 patch doesn’t apply.
