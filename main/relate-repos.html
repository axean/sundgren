Relate repositories#

Note

A prototype.

When a repository was copied (an import, a fork, a mirror) and both went on, git can still tell where they split and how they were synced since, if you have a clone of each. Here copy was cloned from upstream after u2, merged it in twice (m1, m2), merged u6 on a side branch only, and upstream went on to u7:

$ sundgren relate-repos ../upstream

upstream (/work/upstream): 7 commits, 7 on main (1d16b207)
shared: 6 commits, 1 root

  first own 17db64e8 2026-01-05 12:00  a1

Each side has a base, its default branch unless given (--base, --other-base).

  • Copy point, per side: walking the base’s first-parent chain, the first parent of the oldest commit the other base doesn’t have.

  • The copy is the side with the older copy point. Made between: from its copy point to the earlier of the other base’s next first-parent commit and its first own commit. Git dates only, so a copy made later without new commits on either side looks the same.

  • Last sync: the merge base of the two bases.

  • Newest shared: the newest commit both repositories have anywhere, and which refs bring it to a side whose base doesn’t have it.

  • Merges: first-parent merges on one base that brought in commits of the other’s base, with how many and the newest of them.

  • First on: for the commits both bases got after the copy, which base had them first, by the first-parent commit that brought them in.

  • Authors: who wrote the commits one base has and the other doesn’t, with how many and the date of the last, by email as .mailmap maps it. Commits on other branches don’t count, so an old branch that only one side kept is not taken for new work.

  • Named in messages, per repository, over all its commits: the repository paths of GitLab’s See merge request PATH!N lines, with how many, the first and last date and the numbers; and the hosts of http(s):// links. A copy made by an import often names where it came from.

To see it on the map, sundgren graph --compare-repo ../upstream, or sundgren: Show History With Another Repository… in VS Code (History).

Without touching either clone#

Both are read as one bare repository in $XDG_CACHE_HOME/sundgren/join (default ~/.cache), which borrows their objects (objects/info/alternates) and copies their refs on every run: this one’s as they are, the other’s as a remote named after its folder (--name to change it). Nothing is written to either clone. The cache holds only refs and both clones’ .mailmap (this one’s wins); delete it any time.

--format json prints a sundgren.relate-repos/0 document (schema), with the commits above also as a list of marks.
