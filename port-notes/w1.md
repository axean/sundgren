## model

- `LineNo` is i64 and counts are i128 (Python `int()` takes negatives and 2^64 - 1 counters). Values
  outside i128 raise, where Python would keep them.
- `sundgren_core::pyint::py_int` follows `int(str)`: whitespace, sign, `_` between digits. It
  rejects non-ASCII decimal digits, which Python accepts.
- All maps are `BTreeMap`, so Python sees dicts in sorted order. Every producer sorted already.
- The classes are frozen pyclasses wrapping the Rust value. Dict and tuple fields are converted on
  first access and cached. Mutating such a dict changes neither the object nor its equality.
- Shared helper `sundgren-py/src/pyclass.rs` (`dataclass!` macro) gives `__dataclass_fields__`,
  `__match_args__`, the dataclass repr and `__reduce__`, so `dataclasses.asdict/astuple/fields/
  replace/is_dataclass`, copy and pickle work. Needs pyo3's `multiple-pymethods` feature.
- `hash(FileCoverage)` says `unhashable type: 'sundgren.core.model.FileCoverage'` (module-qualified).
- `LineStatus` is a pyclass enum with `.name`/`.value` and the Enum repr, but no `LineStatus("hit")`
  lookup or iteration. Nothing used either.
- New test file `tests/unit/test_model.py` (dataclass helpers, repr, eq/hash/order, copy, pickle).
