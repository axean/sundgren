# Port notes: w2

Decisions and test changes, folded into DECISIONS.md by main at merge.

## PyText

- Patch text, paths, hunk lines and warnings are `sundgren_core::pytext::PyText`: a Python
  str stored as generalized UTF-8 (`s.encode("utf-8", "surrogatepass")`). Lossless for
  surrogateescape-decoded input, and byte order is code point order, so sorting and equality
  match Python. `encode_surrogateescape`/`to_os_bytes`/`to_os_path` give the raw file system
  bytes back. Bindings: `crate::pytext::{pytext_from_py, pytext_into_py}`. (Approved by main.)

## patch

- The parser works on bytes; every delimiter is ASCII, so slicing matches Python's.
- Hunk header numbers are ASCII digits only and must fit i64. Python's `\d` also takes other
  Unicode digits and its ints are unbounded; such headers are now "malformed hunk header".
- A quoted path holding a lone surrogate other than U+DC80..U+DCFF (impossible from
  surrogateescape input) is a "bad quoted path"; Python raised UnicodeEncodeError.
- `PatchError`'s Rust Display approximates `repr` of a bad quoted path; the binding uses Python's
  `repr`, so the ValueError message is identical.
- Fuzzed against the prototype (50k mutated fixture/random patches, incl. surrogates, CRs,
  bad quotes): identical files, warnings, errors and line maps.

## linemap

- Rust `LineMap` keeps `deleted_old`/`added_new` as sorted vectors (accessors), for bisect.
- `build_linemaps` returns one Python object per file under both keys (`m[old] is m[new]`).

## symbols

- `_REGISTRY`, `register_symbolizer`, `get_symbolizer` and the `Symbolizer` protocol stay
  Python. `resolve_spans` calls `get_symbolizer` at call time (`core_symbols::registry_lookup`).
- `resolve_spans` returns new `Span` objects (equal by value), not the symbolizer's own objects.
  Objects with `name/start/end/body_start` attributes are accepted from symbolizers.
- A non-SyntaxError from a symbolizer propagates unchanged (same exception object).
- A path that can't be encoded for the file system (non-surrogateescape lone surrogate) counts as
  an unreadable source and falls back to lcov FN; Python raised UnicodeEncodeError.
- `spans_by_name` stays a Python-level loop in the binding, so it keeps the input objects.
