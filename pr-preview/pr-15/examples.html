Python#

All Python examples use the pytest preset, which sundgren picks because the project has a pyproject.toml. The project is a small module with three functions and their tests.

A patch that only touches tests#

The patch skips test_divide, the only test that calls divide.

mypackage/calc.py#
# mypackage/calc.py
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("b is zero")
    return a / b

def classify(n):
    if n < 0:
        return "neg"
    elif n == 0:
        return "zero"
    return "pos"
tests/test_calc.py#
# tests/test_calc.py
import pytest
from mypackage.calc import add, divide, classify

def test_add():
    assert add(1, 2) == 3

def test_divide():
    assert divide(6, 3) == 2
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)

@pytest.mark.parametrize("n,expected", [(-1, "neg"), (0, "zero"), (5, "pos")])
def test_classify(n, expected):
    assert classify(n) == expected

The patch changes mypackage/calc.py, which is not a test file, so the whole suite runs on both sides. sundgren can’t know which tests reach which code, so any source change runs everything.

Here the test cases come from a fixture in conftest.py. The patch drops the negative sample.

Running only some tests#

The same source change as above, but measured with only one case of the parametrized test_classify. --tests overrides the preset’s choice of tests.

sundgren run --patch big.patch --tests 'tests/test_calc.py::test_classify[5-pos]' --format json --full -o report.json
sundgren run --patch big.patch --tests 'tests/test_calc.py::test_classify[5-pos]' --format text -o report.txt

Tip

Choosing tests with --tests in pytest. Each value is a pytest node ID, so it can be as narrow as you like:

To run

Pass

a test file

tests/test_calc.py

one test

tests/test_calc.py::test_classify

one case of a parametrized test

tests/test_calc.py::test_classify[5-pos]

a test in a class

tests/test_x.py::TestX::test_y

List several values to run several tests. A parametrized case’s ID is its parameter values joined by -; pytest’s --collect-only option lists every ID.

Warning

Quote IDs that contain [ in your shell, as above. Otherwise the shell may treat them as file name patterns.

Only test_classify[5-pos] runs, so add, divide and most of classify count as missed on both sides, and the coverage is 50% before and after. The change itself shows the same as before: the new if line is hit by 5, and the line returning "big" is not.

Your own commands: placeholders#

Instead of a preset, --cmd runs your own commands; repeat it for several commands. --lcov says where they write the lcov file. This example does by hand what the pytest preset does, on the skip_divide patch from the first example:

sundgren run --patch skip_divide.patch --cmd "{python} -m coverage run --data-file={out}/.coverage -m pytest -q {tests}" --cmd "{python} -m coverage lcov --data-file={out}/.coverage -o {lcov}" --lcov "{out}/coverage.lcov" --format json --full -o report.json
sundgren run --patch skip_divide.patch --cmd "{python} -m coverage run --data-file={out}/.coverage -m pytest -q {tests}" --cmd "{python} -m coverage lcov --data-file={out}/.coverage -o {lcov}" --lcov "{out}/coverage.lcov" --format text -o report.txt

The words in braces are placeholders. sundgren fills them in separately for each side and each run, just before it runs the command:

Placeholder

Becomes

In this example

{python}

python on your PATH (or --python)

the interpreter that runs coverage.py and pytest

{tests}

the selected tests, one argument each

nothing: --cmd has no test selection, so all tests run

{out}

a fresh output directory for this side and run

where coverage.py keeps its data file and the lcov file goes

{lcov}

the --lcov value, with its placeholders filled in

{out}/coverage.lcov, so the second command writes the file sundgren reads

{worktree}

the checkout the commands run in

not needed: commands already run inside it

{junit}

the --junit value, or empty

not used

So on the base side, {out} is a directory like out/base/run-1 inside sundgren’s work directory, and the second command writes out/base/run-1/coverage.lcov. On the patched side the same commands write to out/patched/run-1. Every side and run gets its own {out}, so the two sides never overwrite each other’s files.

Tip

  • {worktree} is mostly useful in --env values. For example, if your package is installed in editable mode, set PYTHONPATH to {worktree}/src so each side imports its own code.

  • {tests} on its own expands to one argument per test, or to nothing. Inside a longer argument, the tests are joined with spaces.

  • Placeholders work the same in a preset’s commands, lcov, junit and env values. See the reference.

Rust#

The Rust examples use the cargo-tarpaulin preset. The project is the same three functions in Rust, with unit tests in a tests module.

Note

The Rust presets have no test selection: unless you pass --tests, every patch runs all tests.

A patch that only touches tests#

The patch marks test_divide, the only test that calls divide, with #[ignore].

src/lib.rs#
pub fn divide(a: i64, b: i64) -> Result<i64, &'static str> {
    if b == 0 {
        return Err("b is zero");
    }
    Ok(a / b)
}

pub fn classify(n: i64) -> &'static str {
    if n < 0 {
        "neg"
    } else if n == 0 {
        "zero"
    } else {
        "pos"
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_divide() {
        assert_eq!(divide(6, 3), Ok(2));
        assert_eq!(divide(1, 0), Err("b is zero"));
    }

    #[test]
    fn test_classify() {
        assert_eq!(classify(-1), "neg");
        assert_eq!(classify(0), "zero");
        assert_eq!(classify(5), "pos");
    }
}

A patch that changes a test helper#

Rust has no fixtures; shared test data usually comes from a helper function in the tests module. Here test_classify loops over the cases from samples(), and the patch drops the negative one.

pub fn divide(a: i64, b: i64) -> Result<i64, &'static str> {
    if b == 0 {
        return Err("b is zero");
    }
    Ok(a / b)
}

pub fn classify(n: i64) -> &'static str {
    if n < 0 {
        "neg"
    } else if n == 0 {
        "zero"
    } else {
        "pos"
    }
}

Tip

Choosing tests with --tests in Rust. Each value is a test name filter, passed to the test runner after --, as with cargo’s own test command. The smallest unit is one test function.

To run

Pass

every test whose name contains a word

classify

one test, by its path

tests::test_classify

several tests

several values, for example test_classify and test_divide

exactly one name, not every name containing it

the full path, then --tests=--exact after it

everything except a test

--tests=--skip followed by --tests=test_divide

Runner options like --exact must be attached with =, as shown, or sundgren reads them as its own options.

Warning

A filter that matches nothing runs no tests, and sundgren gives no warning. The report then shows almost nothing covered on that side. Try the filter with cargo’s test command first.
